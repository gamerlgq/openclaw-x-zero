# 2026-05-08 日志

## 飞书 + Codex 代理矛盾修复

### 问题
飞书切换 GPT/Codex 模型后报 `⚠️ Something went wrong`，飞书 bot 无响应。

### 根因
OpenClaw 代理代码 bug：`proxy.enabled=true` 时 `applyProxyEnv()` 主动清空所有 `NO_PROXY` 环境变量，导致：
- 飞书 SDK 被迫走代理 → `global-agent` HTTPS 重定向 URL 循环拼接 → bot identity 探针失败 → 飞书无响应
- 不开代理 → `chatgpt.com` 直连超时（大陆服务器被墙）→ Codex 不可用

### 矛盾
| 路径 | 需要走代理 | 必须直连 |
|------|-----------|---------|
| `chatgpt.com` (Codex API) | ✅ Clash 代理 | ❌ 超时 |
| `open.feishu.cn` (飞书 SDK) | ❌ URL 循环拼接 | ✅ 大陆直连 |

### 解决方案
Patch 文件：`/home/ubuntu/.nvm/versions/node/v24.14.0/lib/node_modules/openclaw/dist/proxy-lifecycle-CTU4IpEB.js`

原代码（第73行）：
```js
for (const key of NO_PROXY_ENV_KEYS) process.env[key] = "";
```

替换为：
```js
const _noProxyVal = process.env["NO_PROXY"] || process.env["no_proxy"] || "open.feishu.cn,*.feishu.cn,*.larksuite.com,127.0.0.1,localhost";
process.env["NO_PROXY"] = _noProxyVal;
process.env["no_proxy"] = _noProxyVal;
process.env["GLOBAL_AGENT_NO_PROXY"] = _noProxyVal;
```

### ⚠️ 注意
- **OpenClaw 升级后此 patch 会被覆盖**，需要重新打
- 服务器在大陆，用 Clash (`http://127.0.0.1:7890`) 翻墙
- `proxy.enabled: true` + `proxy.proxyUrl: http://127.0.0.1:7890`（在 `openclaw.json` 中）

### 换号流程（下次参考）
1. `openclaw onboard --auth-choice openai-codex` 重新登录新账号
2. 确认 `proxy.enabled: true`（如果被改回 false，需要改 `openclaw.json`）
3. 确认 Clash 代理在运行 (`http://127.0.0.1:7890`)
4. 重启 gateway：`openclaw gateway restart`
5. 验证飞书 bot identity 探针成功（日志里 `bot open_id resolved` 不是 `unknown`）
6. 验证 Codex 模型可用（飞书切换模型发消息测试）
7. 如果升级了 OpenClaw → 重新打 NO_PROXY patch
